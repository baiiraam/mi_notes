## 2. 🎯 TEACH IT SUMMARY

### The Big Picture — Week 4 DL

Week 4 covers how modern computer vision models are built, adapted, and generalized — moving from handcrafted features to deep, trainable architectures and then to systems that can learn from unlabeled data.

**Part 1: CNN Architectures.** The evolution from AlexNet to ResNet shows how depth was the main challenge. AlexNet (2012) proved deep CNNs could work with ReLU, Dropout, and GPUs. VGG (2014) showed that stacking small 3×3 filters enables deeper networks with fewer parameters. Inception (2014) introduced multi-scale processing with 1×1 bottlenecks for efficiency. **ResNet (2015) was the breakthrough** — residual (skip) connections solved the vanishing gradient problem, enabling networks with 100+ layers. The key insight: `H(x) = F(x) + x` makes it easy for gradients to flow directly through the network.

**Part 2: Transfer Learning & Data Augmentation.** Once we have powerful models, we need to adapt them to new tasks. **Transfer learning** lets us reuse features learned on massive datasets (ImageNet) — either by freezing weights and training only a new head (feature extraction) or by fine-tuning with a small learning rate. **Data augmentation** artificially creates variations (rotations, flips, color shifts, Mixup, CutMix) so the model learns to ignore irrelevant changes. The rule: augmentations must be label-preserving — if a transformation changes the object identity, it's not valid.

**Part 3: Domain Adaptation & Self-Supervised Learning.** When training and deployment domains differ (e.g., clear images vs rainy weather), **domain adaptation** aligns the distributions. DANN uses a Gradient Reversal Layer to make features domain-invariant through adversarial training. **Self-supervised learning** goes further — it learns from unlabeled data by creating its own supervision signals. SimCLR uses contrastive learning (positive pairs = augmented views of same image, negative pairs = different images). MoCo uses a queue + momentum encoder to enable large dictionaries. BYOL eliminates negative pairs entirely using asymmetric online/target networks.

**Part 4: Text Representations.** The same principles apply to language: words need dense vector representations (embeddings). Word2Vec (CBOW predicts target from context; Skip-gram predicts context from target) and GloVe (factorizes global co-occurrence) learn dense vectors where proximity = similarity. **Subword tokenization** (BPE, WordPiece, SentencePiece) ensures we never face unknown words by breaking rare words into frequent pieces. The limitation: static embeddings can't handle context — "bank" (river) vs "bank" (financial) share one vector, motivating sequence models (RNNs, Transformers).

**The Connecting Thread:** All these techniques aim to make models **generalize beyond their training data** — whether through architecture (ResNet's skip connections), data (augmentation), task adaptation (transfer learning), or representation (embeddings, SSL).

## 3. ⚠️ COMMON PITFALLS IN PRACTICE

**How to use:** These are practical mistakes that happen in code and experiments. Read each pitfall and the fix before your next project.

| Pitfall | Why It Happens | How to Avoid |
|---------|----------------|--------------|
| **1. Data leakage in normalization** | Computing mean/std on the full dataset before splitting — test statistics influence training. | Fit scaler **ONLY on training data**. Transform train, val, test using train's statistics. |
| **2. Catastrophic forgetting in fine-tuning** | Learning rate is too high — the model overwrites useful pre-trained features. | Use **1/10th to 1/100th** of the pre-training learning rate. Start with frozen backbone, gradually unfreeze. |
| **3. Over-augmentation** | Aggressive transformations distort semantic meaning — e.g., rotating a "6" into a "9" breaks the label. | **Visualize your augmentations**. Test them on a few samples. Use RandAugment for automatic magnitude control. |
| **4. Confusing BPE and WordPiece** | Both are subword tokenizers but use different merge criteria — they produce different vocabularies. | **BPE**: raw frequency. **WordPiece**: normalized likelihood (`count(ab)/(count(a)×count(b))`). Check which one your model uses. |
| **5. SSL model collapse** | The network outputs the same constant vector for all inputs — contrastive loss fails without enough negatives. | For BYOL: ensure the target network is a **slow-moving average** of the online network. For SimCLR: use large batches (4096+) or MoCo's queue. |
| **6. Applying augmentation to validation/test** | Augmentation is applied to all data before splitting, or validation data is augmented during evaluation. | **Never augment validation or test**. They must reflect the true distribution. Validation = no augmentation, no transformations. |
| **7. Negative transfer in fine-tuning** | Source domain (ImageNet) is too dissimilar from target (medical X-rays, satellite imagery). Pre-trained features hurt performance. | Compare: train from scratch vs using pre-trained. If pre-trained is **worse**, use domain-specific pre-training or lighter feature extraction. |
| **8. Tuning augmentation on validation** | Adjusting augmentation parameters (rotation degree, color jitter strength) based on validation performance. | **This is data leakage** — you're effectively training on validation data. Use a separate validation set for hyperparameter tuning. |
| **9. Misunderstanding transfer learning strategies** | Assuming fine-tuning is always better than feature extraction for small datasets. | **Small dataset → Feature Extraction** (less risk of overfitting). **Large dataset → Fine-Tuning** (can adapt features safely). |
| **10. Polysemy in static embeddings** | Word2Vec/GloVe give one vector per word — "bank" means both riverbank and financial institution. | Use **contextual embeddings** (ELMo, BERT) for tasks where word sense matters. Static embeddings are still fine for many classification tasks. |

### CNN Architectures

**Model Answer:** The 2012 breakthrough that introduced ReLU, Dropout, and GPU training to vision, proving deep CNNs could beat traditional computer vision methods.

---

<details>
<summary><b>VGG</b> — Try your own first</summary>

**Model Answer:** Demonstrated that stacking small 3×3 filters enables deep networks with fewer parameters while increasing representational power through more non-linearities.

</details>

---

<details>
<summary><b>Inception (GoogLeNet)</b> — Try your own first</summary>

**Model Answer:** Uses multi-scale parallel convolutions (1×1, 3×3, 5×5) with 1×1 bottlenecks for efficiency, enabling wider rather than just deeper networks.

</details>

---

<details>
<summary><b>ResNet</b> — Try your own first</summary>

**Model Answer:** Introduced residual (skip) connections that allow gradients to flow directly through the network, enabling training of hundreds of layers by solving the vanishing gradient problem.

</details>

---

<details>
<summary><b>Residual Connection (Skip Connection)</b> — Try your own first</summary>

**Model Answer:** Adds the input to the output of a layer (`H(x) = F(x) + x`), providing a gradient "highway" that bypasses weight layers and prevents vanishing gradients in deep networks.

</details>

---

<details>
<summary><b>Transfer Learning</b> — Try your own first</summary>

**Model Answer:** Leveraging a model pre-trained on a large dataset (e.g., ImageNet) and adapting it to a smaller target task, drastically reducing data and training requirements.

</details>

---

<details>
<summary><b>Feature Extraction (Transfer Learning)</b> — Try your own first</summary>

**Model Answer:** Using a pre-trained model as a fixed feature extractor — freezing all weights and training only a new classifier on top.

</details>

---

<details>
<summary><b>Fine-Tuning (Transfer Learning)</b> — Try your own first</summary>

**Model Answer:** Unfreezing some or all pre-trained layers and training them further on target data with a small learning rate to adapt features to the new domain.

</details>

---

<details>
<summary><b>Negative Transfer</b> — Try your own first</summary>

**Model Answer:** When the source domain is too dissimilar to the target domain, pre-trained features become irrelevant or misleading, harming performance rather than helping.

</details>

---

<details>
<summary><b>Catastrophic Forgetting</b> — Try your own first</summary>

**Model Answer:** When fine-tuning on a new task with too high a learning rate, the model overwrites useful pre-trained features and forgets what it learned on the source domain.

</details>

---

### Data Augmentation

<details>
<summary><b>Data Augmentation</b> — Try your own first</summary>

**Model Answer:** Artificially expanding the training set by applying label-preserving transformations, forcing the model to become invariant to non-semantic variations.

</details>

---

<details>
<summary><b>Mixup</b> — Try your own first</summary>

**Model Answer:** Blends two images and their labels (`x̃ = λx₁ + (1-λ)x₂`, `ỹ = λy₁ + (1-λ)y₂`), encouraging smooth, linear decision boundaries between classes.

</details>

---

<details>
<summary><b>CutMix</b> — Try your own first</summary>

**Model Answer:** Cuts a patch from one image and pastes it onto another, mixing labels proportionally to patch area; encourages local feature learning and improves localization.

</details>

---

<details>
<summary><b>Domain Adaptation</b> — Try your own first</summary>

**Model Answer:** Techniques that bridge the gap between training (source) and deployment (target) domains when data distributions differ, using feature alignment or adversarial training.

</details>

---

<details>
<summary><b>DANN (Domain-Adversarial Neural Network)</b> — Try your own first</summary>

**Model Answer:** Uses a Gradient Reversal Layer (GRL) to make features domain-invariant — the feature extractor learns to fool a domain classifier, forcing it to ignore domain-specific information.

</details>

---

<details>
<summary><b>Self-Supervised Learning (SSL)</b> — Try your own first</summary>

**Model Answer:** Learning robust representations from unlabeled data by creating supervisory signals from the data itself, often through contrastive or predictive tasks.

</details>

---

<details>
<summary><b>SimCLR</b> — Try your own first</summary>

**Model Answer:** A contrastive SSL method that maximizes agreement between differently augmented views of the same image (positive pairs) and minimizes agreement between different images (negative pairs).

</details>

---

<details>
<summary><b>MoCo (Momentum Contrast)</b> — Try your own first</summary>

**Model Answer:** Uses a dynamic dictionary (queue) of negative samples and a momentum encoder to enable contrastive learning without requiring massive batch sizes.

</details>

---

<details>
<summary><b>BYOL (Bootstrap Your Own Latent)</b> — Try your own first</summary>

**Model Answer:** A non-contrastive SSL method that uses two asymmetric encoders (online + target) with no negative pairs, preventing collapse through a slow-moving average of the online network.

</details>

---

### Text Representations

<details>
<summary><b>Word2Vec — Skip-gram</b> — Try your own first</summary>

**Model Answer:** Predicts context words given a target word; slower to train but better for rare words since each context word provides a separate training signal.

</details>

---

<details>
<summary><b>Word2Vec — CBOW</b> — Try your own first</summary>

**Model Answer:** Predicts a target word from the average of its surrounding context words; faster to train and smoother, but works better for frequent words.

</details>

---

<details>
<summary><b>Negative Sampling</b> — Try your own first</summary>

**Model Answer:** Replaces the expensive full softmax over the vocabulary with binary classification on a small set of sampled negative (word, context) pairs, reducing training cost from O(|V|) to O(k).

</details>

---

<details>
<summary><b>GloVe (Global Vectors)</b> — Try your own first</summary>

**Model Answer:** Learns embeddings by explicitly factorizing global word-word co-occurrence statistics from the entire corpus, unifying count-based and prediction-based approaches.

</details>

---

<details>
<summary><b>Distributional Hypothesis</b> — Try your own first</summary>

**Model Answer:** "A word is characterized by the company it keeps" — words that occur in similar contexts tend to have similar meanings, the foundation of distributional semantics.

</details>

---

<details>
<summary><b>BPE (Byte-Pair Encoding)</b> — Try your own first</summary>

**Model Answer:** A greedy, frequency-driven subword tokenizer that iteratively merges the most frequent adjacent symbol pairs, building a vocabulary from characters up.

</details>

---

<details>
<summary><b>WordPiece</b> — Try your own first</summary>

**Model Answer:** Similar to BPE but merges pairs that maximize corpus likelihood under a language model (`score = count(ab)/(count(a)×count(b))`), favoring statistically surprising combinations.

</details>

---

<details>
<summary><b>SentencePiece</b> — Try your own first</summary>

**Model Answer:** A framework that treats raw text as a Unicode stream (no pre-tokenization), with whitespace encoded as `_`; supports both BPE and Unigram modes, making it language-agnostic.

</details>

---

<details>
<summary><b>Static Embeddings Limitations</b> — Try your own first</summary>

**Model Answer:** Word2Vec and GloVe assign one fixed vector per word type, failing to handle polysemy (multiple meanings) and lacking sequential context needed for language understanding.

</details>

## 7. COMMON MISCONCEPTIONS — WEEK 4 DL

**How to use:** Read each misconception first. Try to identify what's wrong. Then click to reveal the reality.

---

### Misconception 1: "More depth is always better for CNNs."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Deeper networks always perform better. | ResNet was needed because deeper networks **degrade** in accuracy without skip connections. The "degradation problem" makes deeper networks harder to optimize, not just overfit. |

**Key insight:** Depth is powerful but requires architectural innovations (residual connections) to realize the benefits.

</details>

---

### Misconception 2: "Fine-tuning always beats feature extraction."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Fine-tuning is always better than freezing features. | For **small datasets**, fine-tuning can cause **catastrophic forgetting** and overfitting. Feature extraction with a new classifier head is safer and often works better. |

**Rule of thumb:** Small dataset → feature extraction; large, diverse dataset → fine-tuning.

</details>

---

### Misconception 3: "Data augmentation is just about getting more data."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Augmentation just adds more examples. | Augmentation is about **building invariance** — teaching the model that semantic meaning doesn't change under transformations. Mixup/CutMix also regularize the **decision boundary** itself. |

**Key insight:** Augmentation shapes what the model learns to ignore (variations) and what it learns to focus on (the object itself).

</details>

---

### Misconception 4: "More augmentation is always better."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Aggressive augmentation always improves performance. | **Over-augmentation** can create unrealistic images that introduce noise and degrade training. For orientation-sensitive tasks (e.g., digit "6" vs "9"), rotations may break label-preserving assumptions. |

**Rule of thumb:** Augmentations must be **label-preserving**. Test your augmentations visually.

</details>

---

### Misconception 5: "Self-supervised learning is just a cheaper supervised learning."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| SSL is a cost-saving alternative to supervised learning. | SSL often produces **better representations** than supervised pre-training on the same data for downstream tasks, because it learns broader invariances and can leverage orders of magnitude more unlabeled data. |

**Key insight:** SSL isn't a compromise — it's a different and often superior paradigm for representation learning.

</details>

---

### Misconception 6: "Word2Vec and GloVe produce contextual embeddings."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Word2Vec and GloVe understand context. | They produce **static embeddings** — one vector per word regardless of context. "Bank" (river) and "bank" (financial) share the same vector, causing polysemy problems. |

**Key insight:** Static embeddings capture "what a word can mean on average," not "what it means here." Contextual embeddings (ELMo, BERT) solve this.

</details>

---

### Misconception 7: "BPE and WordPiece are the same algorithm."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| BPE and WordPiece are interchangeable. | They differ in **merge criterion**: BPE merges by raw frequency; WordPiece merges by normalized likelihood gain (`count(ab)/(count(a)×count(b))`). This leads to different vocabularies from the same corpus. |

**Key insight:** Even "preprocessing" choices encode modeling assumptions about what makes a useful subword unit.

</details>

---

### Misconception 8: "SentencePiece is just another tokenizer."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|

## Exercise CA-3: Residual Connections Explained

| Question | Your Answer |
|----------|-------------|
| 1. What is the "degradation problem" in deep networks? | |
| 2. Write the mathematical form of a residual block. | |
| 3. How do skip connections help with vanishing gradients? | |
| 4. What is the benefit of identity mapping in ResNet? | |
| 5. Why is `H(x) = F(x) + x` easier to learn than `H(x)` directly? | |

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. Degradation problem | As networks become deeper, training accuracy **saturates and then degrades** — not due to overfitting, but because deeper networks are harder to optimize. |
| 2. Residual block formula | `H(x) = F(x) + x` where `F(x)` is the residual (learned transformation) and `x` is the input via shortcut. |
| 3. Skip connections and gradients | Gradients can flow **directly** through the shortcut connection, bypassing weight layers, preventing exponential decay in very deep networks. |
| 4. Identity mapping benefit | The shortcut connection is just `x` (no learned parameters), so the network can trivially learn identity if needed — it doesn't have to "work" to preserve information. |
| 5. Why residual is easier | If the optimal mapping is identity, it's easier to learn `F(x) = 0` than `H(x) = x`; if the optimal mapping has small changes, residual learning focuses on the **difference** from identity. |

</details>

| 4. What is the advantage of subword tokenization? | |
| 5. What coverage guarantee does subword tokenization provide? | |

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. OOV problem | Word-level vocabularies are fixed at training time; any unseen word at inference becomes an unusable `<UNK>` token. |
| 2. Morphologically rich languages | Every inflected form is a distinct token → vocabulary grows very large (e.g., agglutinative languages with many word forms). |
| 3. Subword tokenization | Breaks rare or unseen words into smaller, frequently occurring pieces (subwords, down to characters) — a middle ground between word and character level. |
| 4. Advantage | Guarantees **full vocabulary coverage** — any string can be represented as a sequence of known subword units. Common words stay whole, rare words decompose. |
| 5. Coverage guarantee | Since subwords can be as small as characters, and characters are always in the vocabulary, **no OOV is possible**. |

</details>

<details>
<summary>📖 Click for Answers</summary>

## Exercise TR-8: Limitations of Static Embeddings

| Question | Your Answer |
|----------|-------------|
| 1. What is the polysemy problem? | |
| 2. Give an example of polysemy. | |
| 3. What does a static embedding represent? | |
| 4. What is missing from static embeddings? | |
| 5. What motivates sequence models? | |

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. Polysemy problem | Word2Vec and GloVe assign **exactly one vector per word type**, regardless of context — words with multiple meanings share a single, averaged representation. |
| 2. Polysemy example | "bank" = financial institution vs riverbank — same vector for both meanings, forcing them to be conflated. |
| 3. What static embeddings represent | "What a word **can** mean on average" — not "what it **means here**." |
| 4. What's missing | **Sequential structure** — no word order or how meaning is composed across a sentence. |
| 5. Motivation for sequence models | Tasks like language modelling, translation, and sentiment analysis require modelling **sequences**, not just individual token identities — leading to RNNs, LSTMs, and Transformers. |

</details>

## Exercise DL-1: Data Leakage in Augmentation

| Question | Your Answer |
|----------|-------------|
| 1. What is data leakage in augmentation? | |
| 2. What is the global normalization pitfall? | |
| 3. What is the duplicate data pitfall? | |
| 4. What is the "tuning on validation" pitfall? | |
| 5. What is the golden rule for augmentation and data splits? | |

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. Data leakage in augmentation | When information from the **test/validation set** "leaks" into the training process through augmentation — giving a false sense of performance. |
| 2. Global normalization pitfall | Calculating mean/std deviation on the **entire dataset** (including test set) before splitting — test statistics influence training. |
| 3. Duplicate data pitfall | Applying different augmentations to the same source image and having **identical images appear in both training and testing sets**. |
| 4. Tuning on validation pitfall | Tuning augmentation parameters (e.g., rotation degree) based on validation performance — effectively "training" on validation data. |
| 5. Golden rule | **Never apply augmentation to validation or test sets** — use them only to expose the model to variance during training. Validation/test must reflect true distribution. |

</details>

## Exercise DL-2: Data Leakage Detection

| Question | Your Answer |
|----------|-------------|
| 1. What are the signs of data leakage? | |
| 2. How can you test for leakage? | |
| 3. Why does leakage create a false sense of performance? | |
| 4. What is the validation protocol for augmentation? | |
| 5. Why must the validation pipeline remain isolated? | |

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. Signs of data leakage | Unrealistically high validation accuracy; performance gap between validation and production; similar images across splits. |
| 2. Testing for leakage | Manually inspect images across splits; check if augmentations applied to validation data; verify normalization statistics computed only on training data. |
| 3. Why false sense of performance | The model has effectively "seen" validation data during training through leakage — performance is inflated and doesn't reflect true generalization. |
| 4. Validation protocol | Validation pipeline must be **strictly isolated** from training transformations — no augmentation, no normalization fit, no duplicate samples. |
| 5. Why isolation matters | To ensure true generalization — the model must perform well on completely unseen data, not data that was indirectly used during training. |

</details>
