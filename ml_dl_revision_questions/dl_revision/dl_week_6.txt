## 2. 🎯 TEACH IT SUMMARY

### The Big Picture — Week 6 DL

Week 6 covers **pretrained language models** — the foundation of modern NLP — from BERT (understanding) through GPT (generation) to RAG (connecting LLMs to external knowledge).

**Part 1: BERT — Deep Bidirectional Representations.** BERT (`Bidirectional Encoder Representations from Transformers`, Devlin et al., 2018) uses the **encoder-only** Transformer stack to learn **deeply bidirectional** representations. Unlike ELMo (which concatenates separate left-to-right and right-to-left LSTMs — "shallow" bidirectionality), BERT's self-attention lets every token attend to every other token at every layer. The input is the sum of **token embeddings** (WordPiece subwords), **segment embeddings** (sentence A vs B), and **learned positional embeddings**. Special tokens: `[CLS]` (classification aggregate), `[SEP]` (separator), `[MASK]` (pretraining placeholder). **Masked Language Modeling (MLM)** masks 15% of tokens and trains the model to predict them using bidirectional context — the 80/10/10 rule (80% `[MASK]`, 10% random token, 10% unchanged) prevents train/inference mismatch. **Next Sentence Prediction (NSP)** trains on sentence pairs (50% real consecutive, 50% random) to learn inter-sentence relationships. Fine-tuning adapts the same encoder to classification ( `[CLS]` head), NER (token-level head), and QA (start/end span prediction). RoBERTa later removed NSP and trained longer, DistilBERT distilled it to be smaller/faster.

**Part 2: GPT — Decoder-Only Generation.** GPT (`Generative Pre-trained Transformer`) uses the **decoder-only** Transformer stack with **causal (masked) self-attention** — each token can only attend to previous tokens, exactly matching generation. The **autoregressive language modeling** objective predicts every next token: `L(θ) = -Σ log P(xₜ | x₁...xₜ₋₁; θ)`. Generation uses **sampling** strategies: **temperature** (T→0 = deterministic/greedy, T>1 = more random), **top-k** (sample from top k tokens), and **top-p/nucleus** (sample from smallest set with cumulative probability ≥ p). **Scaling laws** (Kaplan et al., 2020) show test loss decreases as a power law in model size, data, and compute. **Chinchilla** (Hoffmann et al., 2022) found most models were undertrained — optimal is roughly `D ≈ 20N` tokens. **In-context learning** lets large models adapt to tasks from prompt examples with no weight updates (zero-shot, one-shot, few-shot). **Emergent abilities** (multi-step reasoning, chain-of-thought) appear sharply once model scale crosses a threshold.

**Part 3: Efficient Fine-Tuning & Compression.** **LoRA** (`Low-Rank Adaptation`) freezes pretrained weights and learns a low-rank update `ΔW = BA` where `r ≪ d` — 250× fewer parameters to train. **Quantization** reduces weight precision (FP32 → FP16/INT8/INT4) to shrink memory. **Knowledge distillation** trains a smaller "student" model to mimic a larger "teacher" using soft labels.

**Part 4: Retrieval-Augmented Generation (RAG).** LLMs hallucinate because they generate "probable" text, not "truthful" text. RAG solves this by retrieving relevant documents from a knowledge base and inserting them into the prompt. **Semantic search** uses embedding models to find similar vectors; **keyword search** (BM25/TF-IDF) uses exact matches. **Reciprocal Rank Fusion (RRF)** combines rankings. **Chunking** splits documents into pieces — overlapping chunks preserve context. Vector databases (Weaviate, Pinecone) use **HNSW** (Hierarchical Navigable Small World) for fast approximate nearest neighbor search (logarithmic vs linear scaling).

**The Connecting Thread:** Pretrained encoders (BERT) understand text; pretrained decoders (GPT) generate it; RAG connects both to external knowledge. Scaling laws make progress predictable; LoRA and quantization make deployment affordable.

## 3. ⚠️ COMMON PITFALLS IN PRACTICE

| Pitfall | Why It Happens | How to Avoid |
|---------|----------------|--------------|
| **1. Using BERT for generation** | BERT is encoder-only — can't generate text | Use GPT or encoder-decoder for generation |
| **2. Using GPT for bidirectional tasks** | GPT is causal — misses right context | Use BERT or bidirectional model for classification/understanding |
| **3. Forgetting the 80/10/10 rule in MLM** | 100% [MASK] creates train/inference mismatch | Follow 80% [MASK], 10% random, 10% unchanged |
| **4. Fine-tuning with too high learning rate** | Catastrophic forgetting of pretrained knowledge | Use 10-100× smaller LR (e.g., 2e-5) |
| **5. Not using early stopping for fine-tuning** | Fine-tuning too long → overfitting | 2-4 epochs often enough |
| **6. Using greedy decoding for creative tasks** | Greedy produces repetitive/robotic text | Use temperature + top-p sampling |
| **7. Ignoring the Chinchilla scaling rule** | Too many params, too little data | Target D ≈ 20N tokens |
| **8. Applying LoRA to all layers uniformly** | Some layers need more adaptation | Tune rank per layer; experiment with r |
| **9. Quantizing without calibration** | Naive quantization hurts accuracy | Use GPTQ with calibration dataset |
| **10. Chunking without overlap** | Context cut off at boundaries | Use overlapping chunks (10-25% overlap) |
| **11. Using only semantic search** | Misses exact keyword matches | Combine semantic + keyword with RRF |
| **12. Adding everything to RAG context** | Exceeds context window; expensive | Use retrieval to select only relevant chunks |

<details>
<summary><b>GPT</b> — Try your own first</summary>

**Model Answer:** Generative Pre-trained Transformer — a decoder-only Transformer with causal self-attention, trained with autoregressive language modeling to predict the next token.

---

<details>
<summary><b>Causal Self-Attention</b> — Try your own first</summary>

**Model Answer:** Masks out future positions so token t can only attend to tokens ≤ t — matches left-to-right generation at inference time.

</details>

---

<details>
<summary><b>Autoregressive LM Objective</b> — Try your own first</summary>

**Model Answer:** `L(θ) = -Σ log P(xₜ | x₁...xₜ₋₁; θ)` — predicts every next token from left context only; fully self-supervised from raw text.

</details>

---

<details>
<summary><b>Temperature Sampling</b> — Try your own first</summary>

**Model Answer:** Rescales logits by temperature T — T→0 = greedy/deterministic; T>1 = more random/diverse; T=1 = unmodified distribution.

</details>

---

<details>
<summary><b>Top-k Sampling</b> — Try your own first</summary>

**Model Answer:** Restricts sampling to the k highest-probability tokens; filters out the long, low-probability "tail" of implausible tokens.

</details>

---

<details>
<summary><b>Top-p (Nucleus) Sampling</b> — Try your own first</summary>

**Model Answer:** Samples from the smallest set of tokens whose cumulative probability exceeds p — adapts candidate pool size to model confidence.

</details>

<details>
<summary><b>RAG (Retrieval-Augmented Generation)</b> — Try your own first</summary>

### 🔗 KEY CONNECTION EXPLANATIONS

<details>
<summary><b>Connection 1: How does BERT achieve deep bidirectionality vs ELMo?</b></summary>

```
ELMo (Shallow Bidirectionality)
    │
    ├── Left-to-right LSTM → hidden state
    ├── Right-to-left LSTM → hidden state
    └── CONCATENATE outputs at the end
    → Directions never see each other during training

BERT (Deep Bidirectionality)
    │
    ├── One Transformer Encoder
    ├── Self-attention at EVERY layer
    ├── Token attends to ALL other tokens
    └── Both directions at EVERY layer
    → True bidirectional context throughout

Key Insight: ELMo is "shallow" because bidirectionality is only at the output;
BERT is "deep" because it's built into every layer of representation.
```

</details>

---

<details>
<summary><b>Connection 2: Why does MLM use the 80/10/10 rule?</b></summary>

```
MLM OBJECTIVE
    │
    ├── PROBLEM: [MASK] never appears at fine-tuning time
    │       └── Train/inference mismatch → poor performance
    │
    └── SOLUTION: 80/10/10 Rule
            │
            ├── 80% → [MASK] (learn prediction from context)
            ├── 10% → random token (robust representations for all tokens)
            └── 10% → unchanged (model sees ordinary text too)

Key Insight: The mix forces the model to build representations for EVERY token,
not just the ones marked [MASK], ensuring transfer to fine-tuning.
```

</details>

---

<details>
<summary><b>Connection 3: How do BERT and GPT differ in architecture and use?</b></summary>

```
BERT (Encoder-Only)
    │
    ├── Fully bidirectional self-attention
    ├── MLM + NSP pretraining
    ├── `[CLS]` token for classification
    └── Best for: Understanding, classification, NER, QA
    │
    └── CANNOT generate text

GPT (Decoder-Only)
    │
    ├── Causal (masked) self-attention
    ├── Autoregressive LM pretraining
    ├── Next-token prediction
    └── Best for: Generation, chat, completion
    │
    └── CANNOT use bidirectional context

Key Insight: Architecture dictates capability — bidirectional = understand;
causal = generate. Use the right tool for the job.
```

</details>

---

<details>
<summary><b>Connection 4: How do scaling laws and Chinchilla guide model design?</b></summary>

```
SCALING LAWS (Kaplan et al., 2020)
    │
    ├── Loss ∝ power law in N (parameters)
    ├── Loss ∝ power law in D (data)
    ├── Loss ∝ power law in C (compute)
    └── Predictable improvement with scale

    ↓ But: "How should we spend a fixed compute budget?"

CHINCHILLA (Hoffmann et al., 2022)
    │
    ├── Found most models were undertrained
    ├── Optimal: D ≈ 20N tokens
    └── Smaller model + more data → same compute → better performance

Key Insight: Scaling laws tell us "bigger is better"; Chinchilla tells us
"how to distribute that bigness" between parameters and data.
```

</details>

## 7. COMMON MISCONCEPTIONS — WEEK 6 DL

**How to use:** Read each misconception first. Try to identify what's wrong. Then click to reveal the reality.

---

### Misconception 1: "BERT is just a bigger version of Word2Vec."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| BERT is a more advanced static embedding method. | Word2Vec/GloVe are **static** — one vector per word. BERT is **contextual** — the representation of "bank" changes depending on whether it's in "river bank" or "money bank." BERT uses a Transformer encoder, not a shallow embedding lookup. |

**Key insight:** Static embeddings = one vector per word type; BERT = dynamic vectors per word occurrence.

</details>

---

### Misconception 2: "ELMo and BERT both use bidirectional LSTMs."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| ELMo and BERT are both bidirectional models. | ELMo concatenates separate left-to-right and right-to-left LSTMs at the **end** (shallow bidirectionality). BERT uses **self-attention at every layer** where every token attends to every other token (deep bidirectionality). In ELMo, directions never see each other during training. |

**Key insight:** ELMo = "shallow" bidirectional (concatenation at the end); BERT = "deep" bidirectional (attention throughout).

</details>

---

### Misconception 3: "MLM predicts every token like a language model."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| MLM predicts all tokens in a sequence. | MLM only predicts **15%** of tokens (the masked ones). The unmasked tokens are used as context but have no loss. This makes MLM more efficient than autoregressive LM (which predicts every token) and enables bidirectionality (the model can use right context). |

**Key insight:** MLM = denoising autoencoder for text; AR LM = next-token prediction.

</details>

---

### Misconception 4: "GPT can use bidirectional context during fine-tuning."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| GPT can be fine-tuned to use bidirectional attention. | GPT's architecture is **causal** — masked self-attention is built in. It cannot use bidirectional context without changing the model architecture. Fine-tuning doesn't remove the causal mask. This is why BERT (encoder-only) is better for understanding tasks and GPT (decoder-only) is better for generation. |

**Key insight:** Architecture = capability. Causal attention is structural, not just a training choice.

</details>

---

### Misconception 5: "In-context learning updates the model's weights."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| In-context learning is a form of fine-tuning. | In-context learning updates **no weights**. All adaptation happens within the prompt at inference time via self-attention over the examples. The model's parameters remain completely frozen. It's "learning" in the sense of behavior change, not weight update. |

**Key insight:** In-context learning = inference-time pattern matching, not gradient-based learning.

</details>

---

### Misconception 6: "Scaling laws mean bigger is always better with no trade-offs."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Scaling laws say just make models bigger. | Scaling laws say performance improves predictably with scale, but **compute is finite**. Chinchilla showed that for a fixed compute budget, smaller models on more data can outperform larger models on less data. There's an optimal N/D trade-off: D ≈ 20N tokens. |

**Key insight:** Scaling laws answer "does scale help?" Chinchilla answers "how to distribute scale optimally."

</details>

---

### Misconception 7: "Emergent abilities are predictable from scaling laws."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Scaling laws predict emergent abilities too. | Scaling laws predict **loss** smoothly. **Emergent abilities** (like chain-of-thought reasoning) appear sharply at certain scales — near-random performance, then a jump. They cannot be predicted by extrapolating loss curves from smaller models. |

**Key insight:** Loss scales smoothly; abilities can emerge abruptly. This is why small experiments don't always predict large model behavior.

</details>

---

### Misconception 8: "LoRA is just a way to train fewer parameters."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| LoRA is a parameter-saving trick. | LoRA is based on the observation that weight updates during fine-tuning have **low intrinsic rank**. By learning a low-rank decomposition `ΔW = BA`, it not only saves parameters but also enables **multiple tasks to share the same base model** with swappable (A,B) pairs. This is a structural insight, not just an implementation detail. |

**Key insight:** LoRA = low-rank adaptation, not just parameter reduction. It reveals something about how models adapt.

</details>

---

### Misconception 9: "RAG and fine-tuning are mutually exclusive approaches."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| You either use RAG or fine-tuning, not both. | RAG and fine-tuning are **complementary**. Fine-tuning adapts the model's weights to a domain; RAG provides up-to-date, retrievable information at inference. They can be used together — a fine-tuned model plus RAG often performs better than either alone. |

**Key insight:** Fine-tuning = change weights; RAG = change what information the model has access to. Use both.

</details>

---

### Misconception 10: "RAG eliminates LLM hallucinations completely."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| RAG solves the hallucination problem. | RAG **reduces** hallucinations by grounding responses in retrieved documents, but doesn't eliminate them entirely. If the retrieval is wrong, or if the LLM ignores the retrieved context, hallucinations can still occur. Also, the LLM may still "fill in" gaps with plausible but incorrect information. |

**Key insight:** RAG = hallucination mitigation, not hallucination elimination. Use with careful evaluation.

</details>

---

### Misconception 11: "Quantization always hurts model accuracy significantly."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Quantization reduces model quality substantially. | Modern methods like **GPTQ** can quantize to INT4 with **minimal accuracy loss** (often < 1% on benchmarks). Layer-wise calibration using a small dataset minimizes reconstruction error, preserving the model's capabilities while reducing memory by 8×. |

**Key insight:** Neural networks are robust to numerical precision — most information is in the structure, not the exact bit values.

</details>

---

### Misconception 12: "Knowledge distillation just creates a smaller copy of the teacher."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Distillation = shrink the model with minimal loss. | Distillation uses **soft labels** from the teacher (the full probability distribution), which encode more information than hard labels. The student learns the teacher's "dark knowledge" — e.g., "70% cat, 25% dog, 5% fox" reveals similarity structure. This enables the student to outperform training on labels alone. |

**Key insight:** Distillation transfers knowledge, not just predictions. Soft labels = richer training signal.

</details>

---

### Misconception 13: "Chunking is just about fitting within token limits."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Chunking is a technical limitation to handle context windows. | Chunking also improves **relevance**. A single vector for a whole book is an "average" representation — it can't represent specific chapters or topics well. Chunks let the retriever find the most relevant passage, not just a vague summary. Overlapping chunks preserve context across boundaries. |

**Key insight:** Chunking = better retrieval, not just token management.

</details>

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. Problem solved | Without MLM, a bidirectional model could "cheat" by copying the answer from the input (seeing the word it's supposed to predict). MLM masks tokens to prevent this. |

## Exercise SCALING-3: Efficient Fine-Tuning — LoRA

| Question | Your Answer |
|----------|-------------|
| 1. What problem does LoRA solve? | |

| 5. What is the initialization strategy for LoRA? | |

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. Problem solved | Full fine-tuning of large models is expensive. LoRA adapts models with far fewer trainable parameters. |

|----------|--------|

| 2. Problem with whole documents | Single vector for a book can't represent specific chapters/topics → compresses all content into "average" representation. |
| 3. Overlapping chunking | Chunks overlap by 10-25% to preserve context across boundaries — words near the edge appear in multiple chunks. |
| 4. Semantic chunking | Split by sentences, paragraphs, headers, or function definitions — preserves meaning boundaries. |
| 5. Why improves retrieval | Chunks let the retriever find the most relevant passage, not just a vague summary of the whole document. |

</details>
