### DIMENSIONALITY REDUCTION — DETAILED MAP

```
DIMENSIONALITY REDUCTION
    │
    ├── LINEAR METHODS
    │       │
    │       └── PCA (Principal Component Analysis)
    │               │
    │               ├── Goal: Find low-D subspace
    │               │
    │               ├── Two Equivalent Criteria
    │               │       │
    │               │       ├── Minimize Reconstruction Error
    │               │       │       └── ‖x − x̂‖²
    │               │       │
    │               │       └── Maximize Projected Variance
    │               │               └── ‖z − mean(z)‖²
    │               │
    │               ├── Pythagorean Theorem
    │               │       └── Total Variance = Projected Var + Reconstruction Error
    │               │
    │               ├── Solution
    │               │       └── Top K eigenvectors of covariance matrix Σ̂
    │               │
    │               └── Applications
    │                       ├── Eigenfaces (face recognition)
    │                       ├── Visualization
    │                       └── Preprocessing for classifiers
    │
    └── NON-LINEAR METHODS
            │
            └── t-SNE (t-Distributed SNE)
                    │
                    ├── Specialized for Visualization (2D/3D)
                    │
                    ├── Preserves Local Topology (neighborhoods)
                    │
                    ├── High-D: Gaussian similarities pⱼ|ᵢ
                    │
                    ├── Low-D: Student-t similarities qⱼ|ᵢ
                    │
                    ├── Perplexity: effective # of neighbors (5-50)
                    │
                    ├── Cost: KL Divergence
                    │       └── KL(Pᵢ || Qᵢ) = Σ pⱼ|ᵢ log(pⱼ|ᵢ / qⱼ|ᵢ)
                    │
                    ├── Crowding Problem
                    │       └── Fixed by Student-t (heavier tails)
                    │
                    └── Optimization: Gradient Descent + Momentum
```

### DENSITY ESTIMATION — DETAILED MAP

```
KERNEL DENSITY ESTIMATION (KDE)
    │
    ├── Non-parametric density estimation
    │
    ├── Formula: f̂(x) = (1/(nh)) Σᵢ K((x − xᵢ)/h)
    │
    ├── Kernel Properties
    │       ├── Non-negative: K(x) ≥ 0
    │       ├── Symmetric: K(x) = K(−x)
    │       └── Decreasing: K'(x) ≤ 0 for x > 0
    │
    ├── Common Kernels
    │       ├── Gaussian (most common) — exp(−x²/2)
    │       ├── Triangular — max(1−|x|, 0)
    │       ├── Box — 1 for |x| ≤ 1
    │       └── Triweight — (1−x²)³
    │
    ├── Bandwidth h (key hyperparameter)
    │       ├── Small h → under-smoothing (high variance)
    │       ├── Large h → over-smoothing (high bias)
    │       └── Bias-Variance Tradeoff
    │
    ├── Bandwidth Selection
    │       ├── Silverman's Rule of Thumb
    │       │       └── h ≈ 1.06 × σ × n⁻¹/⁵ (assumes normal)
    │       │
    │       └── Improved Sheather Jones (ISJ)
    │               └── More robust for multimodal data
    │
    └── Weighted KDE: f̂(x) = (1/Σwᵢ) Σᵢ wᵢ (1/h) K((x − xᵢ)/h)
```

### CLUSTERING — DETAILED MAP

```
CLUSTERING
    │
    ├── K-MEANS
    │       │
    │       ├── Hard assignment
    │       ├── Requires K a-priori
    │       ├── Objective: minimize within-cluster variation
    │       │       └── Σⱼ Σᵢ∈Cⱼ ‖xᵢ − µⱼ‖²
    │       ├── Algorithm: Assign → Compute centroids → Repeat
    │       ├── Converges to local minimum (not global)
    │       └── Random initializations → different results
    │
    ├── HIERARCHICAL CLUSTERING
    │       │
    │       ├── Agglomerative (bottom-up) is most common
    │       ├── Produces dendrogram (tree structure)
    │       ├── Doesn't require K a-priori
    │       ├── Linkage Methods (inter-cluster distance)
    │       │       ├── Complete: maximum distance (stable)
    │       │       ├── Average: mean of all pairwise (stable)
    │       │       ├── Single: minimum distance (chaining)
    │       │       └── Centroid: distance between centroids (inversions)
    │       └── Cut dendrogram at desired height → K clusters
    │
    └── GAUSSIAN MIXTURE MODELS (GMMs)
            │
            ├── Probabilistic (generative) clustering
            │       └── Each cluster = Gaussian distribution
            │
            ├── Generative Process
            │       ├── Choose cluster z with prob πₖ
            │       └── Sample x ∼ N(µₖ, Σₖ)
            │
            ├── Marginal: p(x) = Σₖ πₖ N(x|µₖ, Σₖ)
            │
            ├── Parameters: πₖ, µₖ, Σₖ
            │
            ├── Soft assignment (responsibilities)
            │       └── rₙₖ = p(zₙ=k | xₙ)
            │
            ├── EM Algorithm
            │       ├── E-step: compute responsibilities
            │       ├── M-step: update parameters
            │       └── Repeat until convergence
            │
            └── GMMs are universal density approximators
```

### 🔗 KEY CONNECTION EXPLANATIONS

<details>
<summary><b>Connection 1: How are PCA's two criteria equivalent?</b></summary>

```
PCA: Two Equivalent Criteria
    │
    ├── CRITERION 1: Minimize Reconstruction Error
    │       └── min (1/n) Σᵢ ‖xᵢ − x̂ᵢ‖²
    │
    ├── CRITERION 2: Maximize Projected Variance
    │       └── max (1/n) Σᵢ ‖zᵢ − mean(z)‖²
    │
    └── WHY THEY ARE EQUIVALENT
            │
            ├── Total Variance = Projected Variance + Reconstruction Error
            │       └── (Pythagorean Theorem)
            │
            ├── Total Variance is constant (depends only on data)
            │
            └── Therefore: minimizing reconstruction error
                    ⟺ maximizing projected variance

    Key Insight: Both criteria lead to the same subspace!
```

</details>

---

<details>
<summary><b>Connection 2: How does t-SNE improve on SNE?</b></summary>

```
SNE → Symmetric SNE → t-SNE
    │
    ├── SNE (Stochastic Neighbor Embedding)
    │       ├── Asymmetric conditional probabilities pⱼ|ᵢ
    │       └── Gaussian in both high-D and low-D
    │
    ├── Symmetric SNE
    │       ├── Symmetric similarities pᵢⱼ
    │       └── Still Gaussian in low-D
    │
    └── t-SNE (t-Distributed SNE)
            │
            ├── Student-t distribution in low-D
            │       └── Heavier tails → solves crowding problem
            │
            ├── Faster computation
            │       └── Simpler gradients
            │
            └── Better behavior
                    └── Better separation in visualization

    Key Insight: Student-t's heavier tails give more space in low-D,
    allowing points that are far apart in high-D to be far apart in low-D.
```

</details>

---

<details>
<summary><b>Connection 3: How does bandwidth control the bias-variance tradeoff in KDE?</b></summary>

```
BANDWIDTH (h) IN KDE
    │
    ├── SMALL h (Under-smoothing)
    │       │
    │       ├── Many spikes (wiggly)
    │       ├── Low bias (captures details)
    │       ├── High variance (sensitive to data)
    │       └── Risk: overfitting
    │
    ├── LARGE h (Over-smoothing)
    │       │
    │       ├── Smooth curve
    │       ├── High bias (loses details)
    │       ├── Low variance (stable)
    │       └── Risk: underfitting
    │
    └── OPTIMAL h
            │
            ├── Balances bias and variance
            │
            ├── Silverman's Rule: h ≈ 1.06 × σ × n⁻¹/⁵
            │       └── Assumes normal distribution
            │
            └── ISJ algorithm: more robust for multimodal

    Key Insight: h = smoothing parameter — similar to regularization.
```

</details>

---

<details>
<summary><b>Connection 4: How do K-means and GMMs relate?</b></summary>

```
K-MEANS vs GMMs
    │
    ├── K-MEANS
    │       │
    │       ├── Hard assignment (each point belongs to one cluster)
    │       ├── Spherical clusters (implicit)
    │       ├── No probabilities
    │       └── Geometric (distance-based)
    │
    ├── GMMs
    │       │
    │       ├── Soft assignment (responsibilities)
    │       ├── Ellipsoidal clusters (full covariance)
    │       ├── Provides probabilities
    │       └── Probabilistic (generative)
    │
    └── GMMs generalize K-means
            │
            ├── If you force hard assignments in GMM:
            │       └── K-means = GMM with Σₖ = I and hard EM
            │
            ├── K-means = limiting case of GMM
            │
            └── GMMs are more flexible (different shapes, sizes)

    Key Insight: GMMs are a probabilistic version of K-means.
```

</details>

---

<details>
<summary><b>Connection 5: How does EM solve the GMM optimization problem?</b></summary>

```
GMM OPTIMIZATION
    │
    ├── Problem: Maximize log p(X) = Σₙ log [Σₖ πₖ N(xₙ|µₖ, Σₖ)]
    │       │
    │       ├── No closed-form solution
    │       └── Sum inside log → difficult
    │
    ├── If we knew cluster assignments zₙ
    │       │
    │       └── Complete data likelihood: easy to optimize!
    │
    ├── EM SOLUTION
    │       │
    │       ├── E-step: Compute responsibilities
    │       │       └── rₙₖ = p(zₙ=k | xₙ) using Bayes rule
    │       │
    │       ├── M-step: Update parameters
    │       │       ├── πₖ = (1/n) Σₙ rₙₖ
    │       │       ├── µₖ = (Σₙ rₙₖ xₙ) / (Σₙ rₙₖ)
    │       │       └── Σₖ = (Σₙ rₙₖ (xₙ−µₖ)(xₙ−µₖ)ᵀ) / (Σₙ rₙₖ)
    │       │
    │       └── Repeat until convergence
    │
    └── Key Insight: Replace unknown assignments with their expectations.
```

</details>

## 2. COMMON MISCONCEPTIONS — WEEK 6 ML

**How to use:** Read each misconception first. Try to identify what's wrong with it. Then click to reveal the reality.

### Misconception 1: "PCA finds clusters in the data."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| PCA can be used to find clusters in data. | **PCA does NOT find clusters:**
| | • PCA finds directions of **maximum variance** — not clusters |
| | • Clusters may or may not align with principal components |
| | • PCA is often used for **visualization** but it doesn't separate clusters |
| | • t-SNE is better for visualizing clusters |

**Example:**
```
Two clusters in data: PCA may project them on top of each other if the cluster separation isn't along the direction of maximum variance.
```

**Rule:** PCA is for variance, not for clustering. Use t-SNE, K-means, or GMMs for cluster discovery.

</details>

---

### Misconception 2: "t-SNE always gives the same result for the same data."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| t-SNE is deterministic — same data = same plot. | **t-SNE is stochastic (random):**
| | • Different **initializations** → different results |
| | • Different **random seeds** → different results |
| | • Results can vary significantly between runs |
| | • Non-convex optimization (gradient descent with randomness) |

**Example:**
```
Run t-SNE twice on the same MNIST data:
Run 1: digits cluster beautifully
Run 2: clusters are less separated or arranged differently
```

**Rule:** Use a fixed random seed for reproducibility. Always interpret t-SNE plots with caution — they are qualitative, not quantitative.

</details>

---

### Misconception 3: "The crowding problem in t-SNE means the algorithm is broken."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| t-SNE's crowding problem is a flaw that makes it unreliable. | **The crowding problem is the REASON t-SNE works:**
| | • There is more space in high dimensions than low dimensions |
| | • Many high-D points that are moderately far apart cannot all be far apart in 2D |
| | • **Student-t distribution** in low-D has heavier tails → gives more space |
| | • This is a feature, not a bug |

**Analogy:** Like trying to pack 100 people into an elevator — you can't give everyone personal space. Student-t makes the elevator bigger (for far apart points).

</details>

---

### Misconception 4: "Perplexity in t-SNE is just another hyperparameter to guess."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Perplexity is a magic number — just pick 30 and hope for the best. | **Perplexity has a meaningful interpretation:**
| | • Perplexity = smooth measure of **effective number of neighbors** |
| | • Perp = 2ᴴ⁽ᴾ⁾ where H(P) is entropy |
| | • Low perplexity (5-10): focus on very local structure |
| | • High perplexity (30-50): more global structure |

**Rule:**
```
Small dataset (<100 points) → lower perplexity (5-20)
Large dataset (>10,000 points) → higher perplexity (30-50)
Always try multiple perplexity values!
```

</details>

---

### Misconception 5: "KDE and histograms are basically the same thing."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| KDE is just a smooth version of a histogram. | **KDE is fundamentally different:**
| | • **Histogram**: fixed bins → discontinuities, depends on bin boundaries |
| | • **KDE**: continuous, smooth, no bin boundaries |
| | • KDE places a kernel on **every data point** |
| | • KDE is **more data-efficient** than histograms |

**Example:**
```
Histogram: x=0.5 may be in bin [0,1] or [0.4,0.6] depending on bin placement
KDE: x=0.5 gets contribution from every data point based on kernel
```

**Rule:** Use KDE for smooth density estimates; use histograms for quick visualization.

</details>

---

### Misconception 6: "The kernel in KDE must be a Gaussian."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| KDE uses Gaussian kernels — it's the only option. | **Many kernels can be used:**
| | • **Gaussian** (most common) — smooth, infinitely differentiable |
| | • **Triangular** — piecewise linear, finite support |
| | • **Box** — simplest, step-like |
| | • **Triweight** — smooth, finite support |
| | • Kernel choice matters less than bandwidth choice |

**Key Insight:** The **bandwidth h** is far more important than the kernel shape. Bandwidth controls smoothness — kernel choice has minimal impact.

</details>

---

### Misconception 7: "Silverman's rule gives the optimal bandwidth for all data."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Silverman's rule of thumb is the definitive bandwidth selection method. | **Silverman's rule makes a strong assumption:**
| | • Assumes data is **normally distributed** |
| | • Works well for unimodal data |
| | • **Fails for multimodal data** (over-smooths or under-smooths) |
| | • ISJ (Improved Sheather Jones) is more robust |

**Example:**
```
Bimodal data: Silverman may smooth over the valley between modes
ISJ: preserves the bimodal structure
```

**Rule:** Use Silverman as a starting point. For multimodal data, use ISJ or cross-validation.

</details>

---

### Misconception 8: "K-means is deterministic — same data always gives the same clusters."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| K-means is deterministic. | **K-means is NOT deterministic:**
| | • Random **initialization** of centroids |
| | • Different initializations → different local minima |
| | • Results can vary significantly |

**Example:**
```
Run K-means 6 times on the same data:
Results: 235.8, 235.8, 235.8, 320.9, 310.9, 235.8
→ Different local minima!
```

**Rule:** Run K-means multiple times with different initializations. Select the run with the lowest within-cluster variation (inertia).

</details>

---

### Misconception 9: "More clusters in K-means always means better segmentation."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| More clusters = better model. | **Too many clusters = overfitting:**
| | • K-means objective always decreases with more clusters |
| | • At K=N, every point is its own cluster (inertia=0) |
| | • But this is useless for understanding data |
| | • Number of clusters should be **meaningful**, not maximized |

**Example:**
```
Customers: 10,000
K=2: "high spenders" vs "low spenders" (useful, actionable)
K=500: Each cluster has 20 customers (hard to interpret, not useful)
```

**Rule:** Choose K based on domain knowledge, elbow method, or gap statistic. Don't maximize inertia.

</details>

---

### Misconception 10: "Hierarchical clustering always produces the same tree regardless of linkage."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Linkage method doesn't matter — the dendrogram is the same. | **Linkage method drastically affects the dendrogram:**
| | • **Complete**: compact clusters, stable |
| | • **Average**: balanced, good general-purpose |
| | • **Single**: chaining phenomenon (long, stringy clusters) |
| | • **Centroid**: inversions (dendrogram can go 'up' then 'down') |

**Example:**
```
Same data → different dendrograms for different linkages!
```

**Rule:** Choose linkage based on the desired cluster shape. Complete/Average are most commonly used.

</details>

---

### Misconception 11: "Clustering problems always have a 'correct' number of clusters."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| There is one true number of clusters in the data. | **The number of clusters is subjective:**
| | • Depends on the **granularity** of analysis needed |
| | • Different applications need different levels of detail |
| | • A customer segmentation might need 3 clusters for marketing but 10 for product design |
| | • Formal methods (elbow, gap statistic) give suggestions, not answers |

**Example:**
```
Customers:
- Marketing wants 3 segments: "low", "medium", "high" spenders
- Product team wants 10 segments for personalization
→ Both are "correct" for their use case!
```

**Rule:** The number of clusters is a **business decision**, not a statistical one. Context matters.

</details>

---

### Misconception 12: "Gaussian Mixture Models and K-means are completely different algorithms."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| GMMs and K-means are unrelated algorithms. | **GMMs generalize K-means:**
| | • K-means = GMM with **Σₖ = I** and **hard assignments** |
| | • K-means is the limiting case of GMMs |
| | • GMMs provide **soft assignments** (probabilities) |
| | • GMMs can model **different cluster shapes** (covariances) |

**Analogy:** K-means is like a GMM wearing a straightjacket — it only allows spherical clusters. GMMs can stretch and rotate (full covariance).

</details>

---

### Misconception 13: "EM for GMMs always converges to the global optimum."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| EM guarantees finding the best GMM parameters. | **EM converges to a LOCAL optimum:**
| | • The GMM log-likelihood is **non-convex** |
| | • Different initializations → different local optima |
| | • EM can get stuck in poor local minima |
| | • Run EM multiple times with different initializations |

**Example:**
```
GMM with 3 clusters:
Run 1: log-likelihood = -4500 (good)
Run 2: log-likelihood = -5200 (poor)
Run 3: log-likelihood = -4480 (best)
```

**Rule:** Always run EM with multiple random initializations and select the best log-likelihood.

</details>

---

### Misconception 14: "GMMs are only useful for clustering."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| GMMs are just a clustering algorithm. | **GMMs are much more than clustering:**
| | • **Density estimation**: GMMs are universal approximators of densities |
| | • **Anomaly detection**: points with low density are anomalies |
| | • **Generative modeling**: sample new data from the learned distribution |
| | • **Semi-supervised learning**: use GMMs to model unlabeled data |
| | • **Classification**: GMMs can be used as generative classifiers |

**Example:**
```
- Fit GMM to all customers (labeled and unlabeled)
- Use density to estimate confidence
- Use GMM as a classifier with Bayes rule
```

**Rule:** GMMs are a general-purpose density estimation tool, not just a clustering method.

</details>

---

### Misconception 15: "t-SNE can be used as a general-purpose dimensionality reduction for any downstream task."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| t-SNE is a good all-purpose dimensionality reduction method. | **t-SNE is specialized for VISUALIZATION ONLY:**
| | • t-SNE does NOT preserve global distances |
| | • t-SNE cannot be used to train other models on the reduced data |
| | • t-SNE has no out-of-sample extension (new points can't be embedded easily) |
| | • t-SNE is stochastic and non-deterministic |

**What t-SNE is good for:**
```
✅ Visualizing high-dimensional data in 2D/3D
✅ Exploring cluster structure qualitatively
✅ Presenting results to stakeholders
```

**What t-SNE is NOT good for:**
```
❌ Preprocessing for classification (use PCA)
❌ Distance preservation (use PCA/MDS)
❌ Reproducible research (use fixed seed, still not guaranteed)
```

**Rule:** Use PCA for general dimensionality reduction. Use t-SNE only for visualization.

</details>
