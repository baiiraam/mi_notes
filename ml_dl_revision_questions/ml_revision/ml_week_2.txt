## 2. 🎯 TEACH IT SUMMARY

### The Big Picture — Week 2 ML

Week 2 covers the **core linear models** of machine learning — from the simplest regression through regularization to classification, and the probabilistic foundations behind them.

**Part 1: Linear Regression.** The simplest and most interpretable model: `ŷ = wᵀx + b`. The **algebraic view** minimizes Mean Squared Error (MSE) via the **normal equations** `w* = (XᵀX)⁻¹Xᵀy` — a closed-form solution, but fails when `XᵀX` is not invertible. The **geometric view** sees `ŷ` as the projection of `y` onto the column space of `X`, with residuals perpendicular to every feature. The **probabilistic view** assumes Gaussian noise `ε ∼ N(0, σ²)`, and MLE of `w` is exactly least squares. The **Gauss-Markov theorem** guarantees OLS is the Best Linear Unbiased Estimator (BLUE) under classical assumptions. **Polynomial regression** extends linear models via feature expansion `φ(x) = [1, x, x², ...]` — still linear in parameters `w`, so the normal equations still apply. The **bias-variance tradeoff** controls model complexity: as polynomial degree increases, bias falls but variance rises; cross-validation finds the sweet spot.

**Part 2: Regularization & Tuning.** Regularization adds a penalty to the loss to prevent overfitting: `Loss(w) + λ·Penalty(w)`. **Ridge (L2)** shrinks coefficients smoothly toward zero (`λ·||w||₂²`) — useful for correlated features. **Lasso (L1)** can set coefficients exactly to zero (`λ·||w||₁`) — automatic feature selection. **ElasticNet** combines both. Parameters (weights) are learned; hyperparameters (α, λ, degree) are chosen via validation. **Grid search** exhaustively tries combinations; **random search** samples random values and is often more efficient. **Cross-validation** inside hyperparameter search prevents overfitting to one validation split. **Nested CV** gives an unbiased estimate of the entire model-selection procedure. **Learning curves** diagnose bias (both errors high) vs variance (train low, val high) vs data-limited (val still rising) vs noise-limited (both plateau).

**Part 3: Logistic Regression & Naive Bayes.** Logistic regression is a **classifier**, despite the name: `p(y=1|x) = σ(wᵀx+b) = 1/(1+e⁻⁽wᵀx+b⁾)`. Training uses **binary cross-entropy** (derived from MLE under Bernoulli distribution). Coefficients are linear effects on **log-odds** (`log(p/(1-p)) = wᵀx+b`), not probabilities directly. For multiclass, use **One-vs-Rest** or **Softmax**. **Naive Bayes** is a **generative** classifier: it models `P(x|y)` and `P(y)`, then applies Bayes' rule. The "naive" assumption is **conditional independence** given the class: `P(x₁, ..., x_d|y) = Π P(xⱼ|y)` — often false but works surprisingly well. **Multinomial Naive Bayes** is the standard baseline for text classification, with **Laplace smoothing** to handle unseen words. **Logistic regression** is discriminative (models `P(y|x)`), while **Naive Bayes** is generative (models `P(x|y)`). They have different assumptions and strengths; try both as baselines on text problems.

**The Connecting Thread:** Linear regression is the foundation — regularization extends it to high-dimensional settings, logistic regression adapts it to classification, and Naive Bayes offers a probabilistic alternative. All are linear models with different assumptions about the data-generating process.

## 3. ⚠️ COMMON PITFALLS IN PRACTICE

| Pitfall | Why It Happens | How to Avoid |
|---------|----------------|--------------|
| **1. Forgetting to scale features for regularization** | L1/L2 penalties act on coefficients, not feature scales | Use `StandardScaler` inside a Pipeline |
| **2. Using L1 (Lasso) with correlated features** | Arbitrarily selects one, ignores the other | Use **ElasticNet** instead |
| **3. Tuning α on a linear scale** | α matters over orders of magnitude | Search on **log scale**: `10⁻⁴` to `10⁴` |
| **4. Confusing parameters and hyperparameters** | Both called "parameters" informally | Parameters = learned (w); Hyperparameters = chosen (α, degree) |
| **5. Data leakage in target encoding** | Target means computed on full dataset | Use **K-fold cross-fitting** |
| **6. Using accuracy for imbalanced classification** | 99% negative → 99% accuracy trivial | Use **Precision, Recall, F1, PR-AUC** |
| **7. Not tuning the decision threshold** | Default 0.5 is arbitrary | Tune threshold on validation data |
| **8. Forgetting Laplace smoothing in Naive Bayes** | Unseen words → zero probability | Add `α` smoothing |
| **9. Using Naive Bayes when features are highly correlated** | Independence assumption badly violated | Logistic regression may be better |
| **10. Leakage in text vectorization** | Fit vectorizer on full dataset | Fit on **train only**, transform all |

### Linear Regression

<details>
<summary><b>Linear Model</b> — Try your own first</summary>

**Model Answer:** `ŷ = wᵀx + b` — a weighted sum of input features plus bias, where `w` are slopes and `b` is the intercept.

---

<details>
<summary><b>MSE Cost Function</b> — Try your own first</summary>

**Model Answer:** `L(w) = (1/n)||y - Xw||²` — the average squared difference between predictions and actual targets.

</details>

---

<details>
<summary><b>Normal Equations</b> — Try your own first</summary>

**Model Answer:** `XᵀXw = Xᵀy` — the system of equations that gives optimal weights by setting the gradient to zero.

</details>

---

<details>
<summary><b>OLS Closed-Form Solution</b> — Try your own first</summary>

**Model Answer:** `w* = (XᵀX)⁻¹Xᵀy` — the analytical solution for linear regression, but fails when `XᵀX` is not invertible.

</details>

---

<details>
<summary><b>Geometric Interpretation of OLS</b> — Try your own first</summary>

**Model Answer:** `ŷ = Xw*` is the projection of `y` onto the column space of `X`, and residuals are perpendicular to every column of `X`.

</details>

---

<details>
<summary><b>Probabilistic Interpretation of Linear Regression</b> — Try your own first</summary>

**Model Answer:** Assuming Gaussian noise `ε ~ N(0, σ²)`, MLE of `w` is equivalent to ordinary least squares.

</details>

---

<details>
<summary><b>Gauss-Markov Theorem</b> — Try your own first</summary>

**Model Answer:** Under classical OLS assumptions, `w*` is the Best Linear Unbiased Estimator (BLUE) — minimum variance among all linear unbiased estimators.

</details>

---

<details>
<summary><b>Polynomial Regression</b> — Try your own first</summary>

**Model Answer:** Mapping input `x` to `φ(x) = [1, x, x², ..., xᵈ]` gives non-linear decision boundaries in `x`-space while keeping convex optimization in `w`-space.

</details>

---

### Regularization

<details>
<summary><b>Regularized Objective</b> — Try your own first</summary>

**Model Answer:** `argmin_w [Loss(w) + λ·Penalty(w)]` — add a penalty to discourage overly complex models and improve generalization.

</details>

---

<details>
<summary><b>Ridge Regression (L2)</b> — Try your own first</summary>

**Model Answer:** `argmin_w [Loss(w) + λ·||w||₂²]` — shrinks coefficients smoothly toward zero; useful for correlated features.

</details>

---

<details>
<summary><b>Lasso Regression (L1)</b> — Try your own first</summary>

**Model Answer:** `argmin_w [Loss(w) + λ·||w||₁]` — can set coefficients exactly to zero, performing automatic feature selection.

</details>

---

<details>
<summary><b>ElasticNet</b> — Try your own first</summary>

**Model Answer:** Combines L1 sparsity with L2 stability — `Loss(w) + λ·(ρ·||w||₁ + (1−ρ)·||w||₂²)` — better than pure Lasso for correlated features.

</details>

---

<details>
<summary><b>Parameters vs Hyperparameters</b> — Try your own first</summary>

**Model Answer:** Parameters (like `w`) are learned during training; hyperparameters (like `α`, polynomial degree) are chosen before training using validation.

</details>

---

<details>
<summary><b>Grid Search</b> — Try your own first</summary>

**Model Answer:** Exhaustively evaluates every combination of a fixed set of hyperparameter values — cost grows multiplicatively.

</details>

---

<details>
<summary><b>Random Search</b> — Try your own first</summary>

**Model Answer:** Samples hyperparameter values from distributions at random — often more efficient than grid search under the same budget.

</details>

---

<details>
<summary><b>Nested Cross-Validation</b> — Try your own first</summary>

**Model Answer:** Outer loop evaluates model performance, inner loop tunes hyperparameters — gives an unbiased estimate of the entire model-selection procedure.

</details>

---

<details>
<summary><b>Learning Curve</b> — Try your own first</summary>

**Model Answer:** Model performance as a function of training set size — helps diagnose whether more data would help or if the model is noise-limited.

</details>

---

### Logistic Regression

<details>
<summary><b>Logistic Regression Model</b> — Try your own first</summary>

**Model Answer:** `p(y=1|x) = σ(wᵀx + b) = 1/(1 + e⁻⁽wᵀx+b⁾)` — maps a linear score to a probability between 0 and 1.

</details>

---

<details>
<summary><b>Binary Cross-Entropy Loss</b> — Try your own first</summary>

**Model Answer:** `−[y·log(p) + (1−y)·log(1−p)]` — penalizes confident wrong predictions heavily; derived from MLE under Bernoulli distribution.

</details>

---

<details>
<summary><b>Logit (Log-Odds) Interpretation</b> — Try your own first</summary>

**Model Answer:** `logit(p) = log(p/(1−p)) = wᵀx + b` — coefficients are linear effects on log-odds, not directly on probability.

</details>

---

<details>
<summary><b>Softmax (Multiclass)</b> — Try your own first</summary>

**Model Answer:** `p(y=k|x) = exp(zⱼ) / Σⱼ exp(zⱼ)` — turns logits into a valid probability distribution for multiclass classification.

</details>

---

<details>
<summary><b>ROC Curve & AUC</b> — Try your own first</summary>

**Model Answer:** ROC plots TPR vs FPR across all thresholds; AUC is threshold-independent, with 0.5 = random, 1.0 = perfect.

</details>

---

### Naive Bayes

<details>
<summary><b>Discriminative vs Generative</b> — Try your own first</summary>

**Model Answer:** Discriminative (Logistic Regression) models `P(y|x)`; generative (Naive Bayes) models `P(x|y)` and `P(y)` and uses Bayes' rule.

</details>

---

<details>
<summary><b>Bayes' Rule for Classification</b> — Try your own first</summary>

**Model Answer:** `P(y|x) = P(x|y)·P(y) / P(x)` — choose class maximizing `P(x|y)·P(y)` since `P(x)` is the same for all classes.

</details>

---

<details>
<summary><b>The "Naive" Assumption</b> — Try your own first</summary>

**Model Answer:** Features are conditionally independent given the class: `P(x₁, ..., x_d|y) = Πⱼ P(xⱼ|y)` — often false but works well in practice.

</details>

---

<details>
<summary><b>Naive Bayes Variants</b> — Try your own first</summary>

**Model Answer:** Gaussian NB (continuous), Bernoulli NB (binary indicators), Multinomial NB (counts/frequencies — the standard for text).

</details>

---

<details>
<summary><b>Multinomial Naive Bayes</b> — Try your own first</summary>

**Model Answer:** Scores as `score(y) = log P(y) + Σⱼ countⱼ·log P(wordⱼ|y)` using log probabilities to avoid underflow.

</details>

---

<details>
<summary><b>Laplace Smoothing</b> — Try your own first</summary>

**Model Answer:** `P(word|class) = (count + α) / (total + α·|V|)` — prevents unseen words from making a whole class impossible.

</details>

---

<details>
<summary><b>Logistic Regression vs Naive Bayes</b> — Try your own first</summary>

**Model Answer:** Logistic regression is discriminative with a linear decision boundary; Naive Bayes is generative with conditional independence; try both as baselines on text.

</details>

---

<details>
<summary><b>TF-IDF</b> — Try your own first</summary>

**Model Answer:** `tf-idf(term, doc) = tf × log(N / df)` — counts words but discounts very common corpus words like "the".

</details>

---

<details>
<summary><b>Bag-of-Words (BoW)</b> — Try your own first</summary>

**Model Answer:** Ignores word order, counts how often each vocabulary term appears — simple, interpretable, fast, often strong.

</details>

### Linear Regression Formulas

<details>
<summary><b>Linear Model & MSE</b> — Try to recall first</summary>

| **Gradient of MSE** | `∇w L = −(2/n)Xᵀ(y - Xw)` |

<details>
<summary><b>Normal Equations & Solution</b> — Try to recall first</summary>

| **OLS solution** | `w* = (XᵀX)⁻¹Xᵀy` |
| **Fails when** | `XᵀX` is not invertible (multicollinearity or d > n) |

</details>

<details>
<summary><b>MLE for σ²</b> — Try to recall first</summary>

**Formula:** `σ²* = (1/n)||y - Xw*||²`

### Bias-Variance Decomposition

<details>
<summary><b>Bias-Variance</b> — Try to recall first</summary>

| Aspect | Formula |
|--------|---------|
| **Total Error** | `Bias² + Variance + σ²` |
| **High Bias** | Underfitting — train error and val error both high |
| **High Variance** | Overfitting — train error low, val error high |
| **σ²** | Irreducible noise — cannot be eliminated |

</details>

### Diagnosis Quick Reference

<details>
<summary><b>Learning Curve Diagnosis</b> — Try to recall first</summary>

| Symptom | Diagnosis | Fix |
|---------|-----------|-----|
| Train low, Val low, small gap | **High Bias** | More complexity, more features, reduce regularization |
| Train high, Val lower, large gap | **High Variance** | More data, stronger regularization, simpler model |
| Val still rising with data | **Data-limited** | Collect more data |
| Both plateau below target | **Noise-limited** | Improve labels/features |

### 🔗 KEY CONNECTION EXPLANATIONS

<details>
<summary><b>Connection 1: How do the three views of linear regression connect?</b></summary>

```
ALGEBRAIC VIEW                    PROBABILISTIC VIEW
Minimize MSE                       Assume ε ~ N(0, σ²)
L(w) = (1/n)||y - Xw||²            y = wᵀx + b + ε

Set gradient = 0                   Maximize likelihood
Xᵀ(y - Xw) = 0                     MLE of w = OLS

Both give: w* = (XᵀX)⁻¹Xᵀy

GEOMETRIC VIEW
ŷ = Xw* is the projection of y onto Col(X)
Residual e = y - ŷ is perpendicular to Col(X)
Normal equations Xᵀe = 0 are the orthogonality condition

All three views lead to the same solution!
```

**Key insight:** The algebraic view tells you how to compute it; the probabilistic view tells you why it's a good idea (MLE); the geometric view tells you what it actually does (projection).

</details>

---

<details>
<summary><b>Connection 2: How does polynomial regression connect to bias-variance?</b></summary>

```
POLYNOMIAL DEGREE (d)
    │
    ├── d = 1 (Too Simple)
    │       ├── High Bias → Underfitting
    │       ├── Train Error: HIGH, Val Error: HIGH (similar)
    │       └── Fix: Increase d, add features
    │
    ├── d = Optimal (Just Right)
    │       ├── Balanced Bias/Variance
    │       ├── Train Error: MODERATE, Val Error: LOWEST
    │       └── Found by cross-validation
    │
    └── d = 9 (Too Complex)
            ├── High Variance → Overfitting
            ├── Train Error: VERY LOW, Val Error: HIGH
            └── Fix: Regularization, more data

MSE = Bias² + Variance + σ² (Irreducible Noise)
```

</details>

---

<details>
<summary><b>Connection 3: How do L1, L2, and ElasticNet relate?</b></summary>

```
REGULARIZATION: Loss(w) + λ·Penalty(w)
    │
    ├── L2 (Ridge): λ·||w||₂²
    │   ├── Smooth shrinkage
    │   ├── Keeps all features
    │   └── Best for: correlated features
    │
    ├── L1 (Lasso): λ·||w||₁
    │   ├── Sparse selection
    │   ├── Sets weights to zero
    │   └── Best for: feature selection
    │
    └── ElasticNet: λ·(ρ·||w||₁ + (1−ρ)·||w||₂²)
        ├── Sparse + Stable
        ├── Better than pure Lasso for correlated features
        └── l1_ratio: 0 = Ridge, 1 = Lasso
```

**Key insight:** L1 = feature selection; L2 = smooth shrinkage; ElasticNet = both.

</details>

---

<details>
<summary><b>Connection 4: How does validation connect to all other concepts?</b></summary>

```
MODEL COMPLEXITY → VALIDATION → CHOOSE BEST
    │
    ├── Polynomial degree: CV chooses optimal d
    ├── Regularization λ: CV chooses optimal α
    ├── Model selection: CV compares Ridge vs Lasso
    ├── Hyperparameter search: CV inside Grid/Random Search
    └── Nested CV: Inner loop tunes; Outer loop evaluates

LEARNING CURVES → DIAGNOSE → FIX
    ├── High Bias (both errors high) → increase complexity
    ├── High Variance (train low, val high) → more data/regularization
    ├── Data-limited (val still rising) → collect more data    └── Noise-limited (both plateau) → improve labels/features

Without validation, you're guessing — CV is the compass.
```

</details>

---

<details>
<summary><b>Connection 5: How do Logistic Regression and Naive Bayes relate?</b></summary>

```
DISCRIMINATIVE (Logistic Regression)     GENERATIVE (Naive Bayes)
─────────────────────────────────────────────────────────────────
Models P(y|x)                            Models P(x|y) and P(y)
Learns decision boundary directly        Models how each class generates data
"Which class is this?"                   "How likely is this class to generate this?"
Linear decision boundary                 Conditional independence assumed
Needs scaling                            Scaling less important
Works well with enough data              Works well with small data

Both are classifiers, but answer different probability questions
with different assumptions.

Rule of thumb: Try both as baselines on text problems.
```

</details>

### Misconception 1: "Linear regression is just fitting a line — nothing more."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Linear regression is a simple, trivial method. | Linear regression is **rich and powerful**: |
| | • **Probabilistic interpretation**: MLE under Gaussian noise |
| | • **BLUE property**: Best Linear Unbiased Estimator (Gauss-Markov) |
| | • **Geometric interpretation**: Projection onto column space |
| | • **Extensible**: Polynomial features → non-linear boundaries |
| | • **Convex**: Guaranteed global minimum |
| | • **Regularizable**: Ridge, Lasso, ElasticNet extensions |

**Key insight:** Linear regression is the foundation for many advanced methods. Understanding it deeply helps you understand everything else.

</details>

---

### Misconception 2: "Polynomial regression is a completely different model."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Polynomial regression is a separate, non-linear model. | Polynomial regression is **linear regression on transformed features**:
| | • Feature map: `φ(x) = [1, x, x², x³, ..., xᵈ]` |
| | • Model: `ŷ = wᵀφ(x)` — still linear in w! |
| | • Same normal equations apply |
| | • Convex optimization in w-space |

**Key insight:** "Linear" refers to linearity in parameters (w), not in the input features (x).

</details>

---

### Misconception 3: "Ridge and Lasso do the same thing."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Ridge and Lasso are essentially the same regularization method. | **They are fundamentally different:** |

| Aspect | Ridge (L2) | Lasso (L1) |
|--------|------------|------------|
| Effect | Smooth shrinkage | Sparse selection |
| Coefficients | Shrinks toward zero | Can set exactly to zero |
| Feature selection | ❌ No | ✅ Yes |
| Correlated features | Stable | Arbitrary selection |
| Geometric shape | Circle | Diamond |

</details>

---

### Misconception 4: "Grid search is always the best tuning method."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Grid search is comprehensive and should be used whenever possible. | **Random search is often more efficient:**
| | • Grid search explores **fewer distinct values** under the same budget |
| | • Many hyperparameters don't matter much — random search finds the important ones |
| | • Grid search suffers from the **curse of dimensionality** in hyperparameter space |

**Key insight:** Use grid for small spaces (1-2 hyperparameters). Use random for larger spaces. Search α on log scale!

</details>

---

### Misconception 5: "Cross-validation is just for small datasets."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| CV is a technique for small datasets — large datasets only need a single split. | **CV is useful for ALL dataset sizes:**
| | • **Small datasets**: Maximizes training data per fold |
| | • **Large datasets**: Reduces variance of performance estimate |
| | • **Hyperparameter tuning**: Prevents overfitting to one validation split |
| | • **Model selection**: Fair comparison between models |

</details>

### Misconception 6: "Logistic regression is a regression algorithm, not a classifier."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Because it has "regression" in the name, it's for regression tasks. | **Logistic regression is a CLASSIFIER:**
| | • Outputs **probabilities** (p(y=1|x)) |
| | • Applied to **classification** tasks |
| | • Uses **classification loss** (cross-entropy), not MSE |
| | • The name is historical — it's really a classifier |

</details>

### Misconception 7: "Naive Bayes is too simplistic — it never works in practice."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| The "naive" independence assumption makes the model useless for real data. | **Naive Bayes works surprisingly well:**
| | • **Text classification**: Strong baseline, especially with small data |
| | • **Fast training**: No iterative optimization |
| | • **Good with small data**: Doesn't overfit as much as logistic regression |
| | • **Interpretable**: Word probabilities are intuitive |
| | • **Smoothing**: Laplace smoothing handles unseen words |

</details>

---

### Misconception 8: "The 'naive' assumption is about features being independent in the data."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Naive Bayes assumes features are independent in the overall dataset. | **It assumes conditional independence GIVEN the class:**
| | • **Wrong**: `P(x₁, x₂) = P(x₁)·P(x₂)` (unconditional independence) |
| | • **Correct**: `P(x₁, x₂ | y) = P(x₁ | y)·P(x₂ | y)` (conditional independence) |

**Key insight:** Conditional independence is a MUCH weaker assumption!

</details>

---

### Misconception 9: "TF-IDF is always better than raw word counts."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| TF-IDF is the superior feature representation for text classification. | **TF-IDF helps, but it's not always better:**
| | • **Short documents**: TF-IDF can over-penalize |
| | • **Long documents**: TF-IDF often helps |
| | • **Some domains**: Common words matter (e.g., style classification) |

**Rule:** Try both — let validation decide.

</details>

---

### Misconception 10: "Accuracy is the only classification metric that matters."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Higher accuracy = better classifier. Period. | **Accuracy can be dangerously misleading:**
| | • **Imbalanced classes**: 99% accuracy from predicting majority class |
| | • **Different error costs**: FP and FN have different consequences |
| | • **Business alignment**: Accuracy doesn't measure business impact |

**Example:**
```
Fraud detection: 99% legit, 1% fraud
Model A: always predicts "legit" → 99% accuracy (bad!)
Model B: catches 90% fraud, 95% legit → 94.95% accuracy (good!)
```

</details>

---

### Misconception 11: "Laplace smoothing adds noise to the data."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Laplace smoothing corrupts the data by adding artificial counts. | **Laplace smoothing is principled Bayesian inference:**
| | • It adds **pseudo-counts**, not noise |
| | • It prevents **zero probabilities** for unseen words |
| | • It's a form of **Bayesian prior** (uniform over words) |

**Key insight:** Smoothing is about **robustness**, not corruption.

</details>

---

### Misconception 12: "More regularization is always better."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Adding more regularization always improves the model. | **Too much regularization = underfitting!**
| | • λ too large → coefficients too small → model too simple |
| | • Underfitting: train error high, val error high |

**The sweet spot:**
```
If train loss ≫ val loss → Too much regularization (underfitting)
If train loss ≪ val loss → Too little regularization (overfitting)
```

</details>

## Exercise LRG-1: Logistic Regression Fundamentals

| Question | Your Answer |
|----------|-------------|
| 1. What is the logistic (sigmoid) function? | |
| 2. How does logistic regression convert a linear score to a probability? | |
| 3. What is the decision boundary for logistic regression? | |
| 4. What is the loss function (binary cross-entropy)? | |

<details>
<summary>📖 Click for Answers</summary>

| Question | Answer |
|----------|--------|
| 1. Sigmoid function | `σ(z) = 1/(1 + e⁻ᶻ)` — maps any real number to (0,1). |
| 2. Linear score → probability | `z = wᵀx + b`, then `p(y=1|x) = σ(z) = 1/(1 + e⁻⁽wᵀx+b⁾)` |
| 3. Decision boundary | `wᵀx + b = 0` (a hyperplane). At threshold 0.5: σ(z) ≥ 0.5 ⇔ z ≥ 0. |
| 4. Binary cross-entropy loss | `−[y·log(p) + (1−y)·log(1−p)]` — penalizes confident wrong predictions heavily. |

</details>

<summary>📖 Click for Answers</summary>

### Fill in all blanks:

**Linear Regression Model:**

`argmin_w [Loss(w) + ___________]`

**Logistic Regression Model:**

**Binary Cross-Entropy:**
`L = ___________`

**Logit (Log-Odds):**
`log(p/(1-p)) = ___________`

**Softmax (Multiclass):**
`p(y=k|x) = ___________`

**Bayes' Rule:**
`P(y|x) = ___________`

**Naive Assumption:**
`P(x₁, ..., x_d | y) = ___________`

**Laplace Smoothing:**
`P(word|class) = ___________`

**TF-IDF:**
`tf-idf(term, doc) = ___________`

**Bias-Variance Decomposition:**
`Total Error = ___________ + ___________ + ___________`

<details>
<summary>📖 Click for Answers</summary>

**Linear Regression Model:**
`ŷ = **wᵀx + b**` (single prediction), `ŷ = **Xw**` (batch form)

**MSE Cost Function:**
`L(w) = **(1/n)||y - Xw||²**`

**OLS Solution:**
`w* = **(XᵀX)⁻¹Xᵀy**` (fails when **XᵀX is not invertible**)

**Polynomial Feature Expansion:**
`φ(x) = **[1, x, x², x³, ..., xᵈ]ᵀ**`

**Ridge (L2) Objective:**
`argmin_w [Loss(w) + **λ·||w||₂²**]`

**Lasso (L1) Objective:**
`argmin_w [Loss(w) + **λ·||w||₁**]`

**ElasticNet Objective:**
`argmin_w [Loss(w) + **λ·(ρ·||w||₁ + (1−ρ)·||w||₂²)**]`

**Logistic Regression Model:**
`p(y=1|x) = **σ(wᵀx + b) = 1/(1 + e⁻⁽wᵀx+b⁾)**`

**Binary Cross-Entropy:**
`L = **−[y·log(p) + (1−y)·log(1−p)]**`

**Logit (Log-Odds):**
`log(p/(1-p)) = **wᵀx + b**`

**Softmax (Multiclass):**
`p(y=k|x) = **exp(zⱼ) / Σⱼ exp(zⱼ)**`

**Bayes' Rule:**
`P(y|x) = **P(x|y)·P(y) / P(x)**`

**Naive Assumption:**
`P(x₁, ..., x_d | y) = **Πⱼ P(xⱼ | y)**`

**Laplace Smoothing:**
`P(word|class) = **(count + α) / (total + α·|V|)**`

**TF-IDF:**
`tf-idf(term, doc) = **tf(term, doc) × log(N / df(term))**`

**Bias-Variance Decomposition:**
`Total Error = **Bias² + Variance + Irreducible Error (σ²)**`
