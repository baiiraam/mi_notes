## 2. 🎯 TEACH IT SUMMARY

### The Big Picture — Week 3 ML

Week 3 covers the **foundation of every ML project**: preparing data, engineering features, and visualizing insights. These are the steps that consume 60-80% of a data scientist's time and often determine model success more than algorithm choice.

**Part 1: Data Preparation.** The core principle is **"Garbage in, garbage out"** — the quality of your output is strictly limited by the quality of your input. The data preparation pipeline is iterative: **Raw Data → Inspect → Clean → Impute → Encode → Visualize**. Common data quality issues include missing values, duplicates, outliers, inconsistent formatting, and wrong data types. **Missing values** come in three types: MCAR (missing completely at random — safe to delete), MAR (missing depends on observed variables — impute validly), and MNAR (missing depends on the missing value itself — highest bias risk). **Imputation** strategies range from simple (mean, median, mode) to advanced (KNN, MICE, forward/backward fill). **Encoding** categorical variables depends on type: nominal → One-Hot, ordinal → Label/Ordinal, high-cardinality → Target or Frequency Encoding. **The golden rule:** Never resample/transform/test on the test set — fit everything on train only.

**Part 2: Feature Engineering.** "Applied ML is basically feature engineering" — Andrew Ng. Features should give the model "pre-digested" knowledge. **Numerical transformations** include scaling (Min-Max for NNs/KNN, Z-score for most models, Robust for outliers), log/power transforms for skewed data, binning, and polynomial/ratio features. **Temporal features** extract year/month/day/hour and use sin/cos for cyclical encoding (hours, months). **Text features** include Bag-of-Words, TF-IDF (downweights common words), and embeddings. **Aggregation features** compute group-level statistics per entity. **Feature selection** methods are Filter (statistical scores, fast), Wrapper (RFE, accurate but slow), and Embedded (Lasso/tree importance, fast and accurate). Always wrap transformations in a Pipeline to prevent leakage.

**Part 3: Data Visualization.** **Anscombe's Quartet** demonstrates that identical summary statistics can produce completely different plots — visualization catches what numbers hide. **Tufte's Data-Ink Ratio** says "above all else show the data" — remove chartjunk, maximize data ink. **Gestalt principles** (proximity, continuity, similarity, closure, enclosure, figure/ground) explain how humans group visual elements. **Color** should be used intentionally: sequential for ordered data, diverging for meaningful midpoints, qualitative for categories. **Chart selection** matters: bar for comparisons, line for trends, scatter for relationships, box for distributions. **Storytelling with data** has four components: Context (who+why), Conflict (the question), Resolution (answer obvious in 5 seconds), Action (what to do next).

**The Connecting Thread:** Data preparation, feature engineering, and visualization are not "pre-work" — they are the most important work. A simple model on clean, well-engineered data beats a complex model on dirty data every time.

## 3. ⚠️ COMMON PITFALLS IN PRACTICE

| Pitfall | Why It Happens | How to Avoid |
|---------|----------------|--------------|
| **1. Scaling before splitting** | Test set statistics leak into training | Fit scaler on **TRAIN only**; transform all |
| **2. Target encoding without K-fold** | Target information leaks from validation | Use **K-fold cross-fitting** |
| **3. One-hot encoding high-cardinality features** | Creates hundreds of columns → sparse, overfitting | Use **Target/Frequency Encoding** |
| **4. Deleting rows with missing values without checking MCAR** | Biases model if MAR/MNAR | Check missingness type first; impute if not MCAR |
| **5. Removing outliers without domain knowledge** | Fraud/rare events ARE outliers | Understand WHY outlier exists before removing |
| **6. Not using Pipelines** | Transformations differ between train and inference | Always use `sklearn.pipeline.Pipeline` |
| **7. Forgetting cyclical encoding for time features** | Hour 23 and 0 appear far apart numerically | Use `sin`/`cos` encoding |
| **8. Using accuracy for imbalanced data** | 99% negative → 99% accuracy trivial | Use **Precision, Recall, F1, PR-AUC** |
| **9. Not visualizing data before modeling** | Missing patterns invisible in numbers | Always do EDA first |
| **10. Using pie charts with >5 categories** | Human eye can't compare angles | Use **bar chart** or **donut** with "Other" |

</details>

### Feature Engineering

<details>
<summary><b>Feature Engineering</b> — Try your own first</summary>

**Model Answer:** Using domain knowledge to create, transform, or select input variables that make machine learning algorithms work better — "Applied ML is basically feature engineering" (Andrew Ng).

---

<details>
<summary><b>Min-Max Normalization</b> — Try your own first</summary>

**Model Answer:** `x' = (x − min)/(max − min)` — scales to [0,1] range; best for neural networks/KNN/SVM but sensitive to outliers.

</details>

---

<details>
<summary><b>Z-Score Standardization</b> — Try your own first</summary>

**Model Answer:** `x' = (x − μ)/σ` — transforms to mean=0, std=1; the most commonly used scaling method; robust to outliers.

</details>

---

<details>
<summary><b>Robust Scaling</b> — Try your own first</summary>

**Model Answer:** `x' = (x − median)/IQR` — uses median and IQR; resistant to outliers; best for data with outliers you cannot remove.

</details>

---

<details>
<summary><b>Log Transform</b> — Try your own first</summary>

**Model Answer:** Reduces right-skew (income, prices, counts), stabilizes variance, and improves linear model fit; use `log(x+1)` when data includes zeros.

</details>

---

<details>
<summary><b>Box-Cox Transform</b> — Try your own first</summary>

**Model Answer:** `((x^λ − 1)/λ)` — finds optimal λ automatically; data must be positive; use `PowerTransformer(method='box-cox')`.

</details>

---

<details>
<summary><b>Cyclical Encoding</b> — Try your own first</summary>

**Model Answer:** Uses `sin` and `cos` to preserve circular structure for hours, months, and days of week — hour 23 and hour 0 map to the same point.

</details>

---

<details>
<summary><b>TF-IDF</b> — Try your own first</summary>

**Model Answer:** `tf-idf(term, doc) = tf × log(N / df)` — counts words but discounts very common corpus words like "the"; standard for document classification.

</details>

### Missing Value Mechanisms

<details>
<summary><b>MCAR, MAR, MNAR</b> — Try to recall first</summary>

| Type | Meaning | Example | Action |
|------|---------|---------|--------|
| **MCAR** | Missing completely at random | Sensor randomly drops 5% of readings | Safe to delete |
| **MAR** | Missing depends on observed variables | Men less likely to report weight | Impute validly |
| **MNAR** | Missing depends on missing value itself | High earners skip salary field | Highest bias risk |

</details>

### Missing Value Decision Thresholds

<details>
<summary><b>Thresholds</b> — Try to recall first</summary>

| Missing Rate | Recommended Strategy |
|--------------|---------------------|
| **< 5%** | Almost any strategy works |
| **5–20%** | Impute carefully |
| **20–40%** | Consider adding missingness indicator |
| **> 40%** | Consider dropping column |

</details>

### Scaling Methods

<details>
<summary><b>Scaling Methods</b> — Try to recall first</summary>

| Method | Formula | Best For | Outlier Sensitivity |
|--------|---------|----------|---------------------|
| **Min-Max** | `(x − min)/(max − min)` | NNs, KNN, SVM, images | High |
| **Z-Score** | `(x − μ)/σ` | Linear/logistic regression, PCA, SVM | Low (most common) |
| **Robust Scaling** | `(x − median)/IQR` | Data with outliers | Very low |

</details>

---

### Transformations

<details>
<summary><b>Log & Power Transforms</b> — Try to recall first</summary>

| Transform | Formula | Use When |
|-----------|---------|----------|
| **Log** | `log(x)` | Right-skewed data (income, prices) |
| **Log1p** | `log(x+1)` | Data includes zeros |
| **Box-Cox** | `((x^λ − 1)/λ)` | Positive data only, finds optimal λ |
| **Yeo-Johnson** | Modified Box-Cox | Handles zero and negative values |

</details>

### Encoding Methods

<details>
<summary><b>Encoding Methods</b> — Try to recall first</summary>

| **One-Hot Encoding** | Nominal, few categories (<15) | Column explosion |
| **Target Encoding** | High-cardinality nominal | Leakage risk (use K-fold) |
| **Frequency Encoding** | High-cardinality nominal | Loses category distinction |

</details>

### Feature Selection Methods

<details>
<summary><b>Filter, Wrapper, Embedded</b> — Try to recall first</summary>

### 🔗 KEY CONNECTION EXPLANATIONS

<details>
<summary><b>Connection 1: Why does data prep consume 60-80% of a data scientist's time?</b></summary>

```
DATA PREP IS THE FOUNDATION FOR EVERYTHING THAT FOLLOWS
    │
    ├── RAW DATA → INSPECT
    │       │
    │       ├── Profile: df.info(), df.describe()
    │       └── Identify issues: missing, duplicates, outliers, format
    │
    ├── CLEAN
    │       │
    │       ├── Duplicates removed → prevents training/test leakage
    │       ├── Outliers handled → prevents model distortion
    │       └── Formatting standardized → enables groupBy/joins
    │
    ├── IMPUTE
    │       │
    │       ├── MCAR → safe to delete
    │       ├── MAR → impute with predictors
    │       └── MNAR → add missingness indicator
    │
    ├── ENCODE
    │       │
    │       ├── Nominal → One-Hot Encoding
    │       ├── Ordinal → Ordinal/Label Encoding
    │       └── High-cardinality → Target/Frequency Encoding
    │
    └── VISUALIZE
            │
            └── EDA catches issues before modeling
```

## 7. COMMON MISCONCEPTIONS — WEEK 3 ML

**How to use:** Read each misconception first. Try to identify what's wrong. Then click to reveal the reality.

---

### Misconception 1: "Data preparation is just a one-time step before modeling."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Data prep is "pre-work" — you clean once and move on. | Data prep is **iterative** — you will loop back many times: |
| | • New issues discovered during EDA → go back |
| | • Feature engineering reveals new patterns → go back |
| | • Model diagnostics reveal issues → go back |
| | • Production data changes → update pipeline |

**Rule:** Data prep is never "done." It's a continuous process throughout the project lifecycle.

</details>

---

### Misconception 2: "Deleting rows with missing values is always the safest option."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| If in doubt, just delete rows with missing values. | **Deletion is only safe under MCAR:** |
| | • **MCAR** → deletion is unbiased |
| | • **MAR** → deletion biases the model |
| | • **MNAR** → deletion biases the model |

**Rule:** Understand WHY data is missing before deciding HOW to handle it. When in doubt, impute.

</details>

---

### Misconception 3: "One-Hot Encoding is the best encoding method for all categorical variables."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| One-Hot Encoding is the standard — use it for everything. | **OHE fails with high cardinality:**
| | • 800 cities → 799 columns (curse of dimensionality) |
| | • Sparse data → wasted memory and compute |
| | • Rare categories → overfitting |

**Rule:** Match encoding to data type AND model type. OHE is not universal!

</details>

---

### Misconception 4: "Outliers should always be removed — they corrupt the model."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Outliers are errors that must be removed. | **Outliers can be valuable signal:**
| | • **Fraud detection** — fraud IS an outlier! |
| | • **Rare disease detection** — the outlier IS the case |
| | • **Anomaly detection** — outliers are what you're looking for |

**Rule:** Understand WHY an outlier exists before removing it.

</details>

---

### Misconception 5: "Feature engineering is optional — the model will learn everything it needs."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Deep learning learns features automatically — no need for feature engineering. | **Feature engineering is still essential:**
| | • Andrew Ng: "Applied ML is basically feature engineering" |
| | • A well-engineered feature > algorithm choice |
| | • Models can't learn cycles from raw timestamps |
| | • Models can't derive ratios (debt/income) |

**Rule:** Give the model "pre-digested" knowledge.

</details>

---

### Misconception 6: "Feature scaling is only needed for distance-based algorithms like KNN."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Only KNN and SVM need scaling — others are fine. | **Many algorithms need scaling:**
| | • **Linear/Logistic Regression** — coefficients depend on scale |
| | • **PCA** — variance dominated by larger scales |
| | • **Neural Networks** — gradients affected by input scales |
| | • **Only tree-based models** are scale-invariant |

**Rule:** Scale for most models. Only trees are truly scale-invariant.

</details>

---

### Misconception 7: "Target encoding is always dangerous — just avoid it."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Target encoding causes data leakage — never use it. | **Target encoding is powerful when done correctly:**
| | • Use **K-fold cross-fitting** to prevent leakage |
| | • Compute target means on training folds only |
| | • Never compute on full dataset before validation |
| | • Often one of the most powerful high-cardinality encodings |

**Rule:** Target encoding is powerful but dangerous — use it carefully with K-fold.

</details>

---

### Misconception 8: "Missing values only matter if there are a lot of them."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| If <5% missing, you can ignore it. | **Missingness pattern matters more than quantity:**
| | • Even 1% missing can bias your model if MNAR |
| | • A 1% missing indicator could be highly predictive |
| | • The FACT of missingness can be the signal |

**Rule:** Always check: does the FACT of being missing predict your target?

</details>

---

### Misconception 9: "Visualization is just for presentation — not for analysis."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Charts are for communicating results, not for analysis. | **Visualization is a critical analysis tool:**
| | • **Anscombe's Quartet** — identical stats, different plots |
| | • Outliers jump out visually in seconds |
| | • Relationships invisible in correlation coefficients become obvious |
| | • EDA is impossible without visualization |

**Rule:** ALWAYS visualize before modeling. It's not optional — it's essential.

</details>

---

### Misconception 10: "More features always means a better model."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| Adding more features always helps the model learn better. | **More features can make the model WORSE:**
| | • **Overfitting** — model fits noise instead of signal |
| | • **Curse of dimensionality** — distances meaningless |
| | • **Multicollinearity** — unstable coefficients |
| | • **Slower training** — 10× features = 10× slower |

**Rule:** Feature selection is critical. More features ≠ better model.

</details>

---

### Misconception 11: "Time features don't need special encoding — just use the raw timestamp."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| A timestamp is a number — the model can learn time patterns. | **Raw timestamps are useless for cyclic patterns:**
| | • Model sees hour 23 and hour 0 as 23 apart |
| | • In reality, they're only 1 hour apart (circular) |
| | • **Solution**: Sin/Cos encoding for cycles |

**Rule:** Cyclic features (hours, months, days) need sin/cos encoding.

</details>

---

### Misconception 12: "A chart with more data is always more informative."

<details>
<summary><b>Click for Reality Check</b></summary>

| Misconception | Reality |
|---------------|---------|
| More data, colors, and details make charts more informative. | **Chartjunk obscures the insight:**
| | • Too many colors (15 in a pie) = impossible to distinguish |
| | • 3D charts distort perception |
| | • Truncated y-axes exaggerate differences |
| | • Chartjunk adds noise without adding information |

**Rule:** Every chart should answer one question for one audience. Remove everything else.

</details>

<details>
<summary>📖 Click for Answers</summary>

**Data Preparation Pipeline:**
`Raw Data → **Inspect** → **Clean** → **Impute** → **Encode** → **Visualize**`

**Garbage In, Garbage Out:** The quality of your output is strictly limited by the quality of your **input**.

**Missing Value Types:**
- MCAR: **Missing Completely at Random** (safe to delete)
- MAR: **Missing at Random** (impute validly)
- MNAR: **Missing Not at Random** (highest bias risk)

**Scaling Methods:**
- Min-Max: `x' = **(x − min)/(max − min)**`
- Z-Score: `x' = **(x − μ)/σ**`
- Robust Scaling: `x' = **(x − median)/IQR**`

**Encoding Methods:**
- Nominal, few categories → **One-Hot Encoding**
- Ordinal → **Ordinal/Label Encoding**
- High-cardinality → **Target/Frequency Encoding**

**Feature Selection Methods:**
- **Filter** (statistical scores, fast)
- **Wrapper** (RFE, accurate but slow)
- **Embedded** (Lasso/tree importance)

**Data-Ink Ratio (Tufte):**
`Data-Ink Ratio = **Ink used to display data** / **Total ink used**`

**Gestalt Principles:**
- **Proximity** (close = related)
- **Continuity** (eyes follow lines)
- **Similarity** (same color = same category)
- **Closure** (brain completes shapes)

</details>
